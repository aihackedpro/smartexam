# Product Requirements — SmartExam

## 1. วิสัยทัศน์ผลิตภัณฑ์

SmartExam เป็นเครื่องมือ local-first สำหรับครูไทย ช่วยลดขั้นตอนการสร้างข้อสอบ
เตรียมกระดาษคำตอบ ตรวจข้อสอบด้วยโทรศัพท์ และดูรายงานผล โดยออกแบบให้ใช้งานง่ายบนมือถือ
และยังทำงานได้เมื่ออินเทอร์เน็ตไม่เสถียร

## 2. ผู้ใช้หลัก

- ครูผู้สอนที่ต้องเตรียมและตรวจข้อสอบด้วยตนเอง
- ครูที่ใช้โทรศัพท์เป็นอุปกรณ์หลักและต้องการพื้นที่แตะ/ตัวอักษรที่อ่านง่าย
- โรงเรียนที่มีอินเทอร์เน็ตไม่สม่ำเสมอและต้องการรักษาข้อมูลไว้ในอุปกรณ์ก่อน

ห้ามใช้ข้อมูลนักเรียนจริงใน fixture, test, screenshot หรือ log ของโครงการ

## 3. ขอบเขตเวอร์ชัน 1.0 แบบ Local-first

1. สร้างข้อสอบปรนัย 2–5 ตัวเลือก กำหนดเฉลยและคะแนนรายข้อ
2. บันทึกข้อสอบและผลตรวจลง IndexedDB พร้อม revision และ autosave
3. สร้างกระดาษคำตอบขาวดำ A4 ตามจำนวนข้อและตัวเลือก
4. ถ่ายหรือเลือกภาพกระดาษคำตอบเพื่อให้ครูเทียบและยืนยันผล
5. ส่งคำตอบกำกวมเข้าสถานะรอตรวจโดยไม่เดาหรือให้คะแนน
6. สรุปคะแนน วิเคราะห์รายข้อ ตรวจทาน และส่งออก CSV
7. สำรอง/กู้คืน JSON แบบ transaction และไม่สร้างรายการซ้ำ
8. ตรวจ Activate Key แบบออฟไลน์โดยไม่เก็บ Key เต็ม
9. PWA, offline app shell และ UI mobile-first ภาษาไทย

## 4. Functional Requirements

### การสร้างข้อสอบ

- ข้อสอบมีชื่อ รายวิชา ระดับชั้น คำชี้แจง คำถาม ตัวเลือก เฉลย และคะแนน
- เพิ่ม ลบ และทำสำเนาคำถามได้
- validation ต้องป้องกันข้อสอบไม่มีชื่อ ไม่มีข้อ ตัวเลือกว่าง และคะแนนไม่ถูกต้อง
- การแก้ไขต้องบันทึกอัตโนมัติและกู้ draft ชั่วคราวได้เมื่อแอปปิดก่อนบันทึก

### กระดาษคำตอบและการพิมพ์

- ใช้ขาวดำ ขนาด A4 และมี marker อ้างอิงสี่มุม
- จำนวนวงคำตอบต้องตรงกับตัวเลือกของแต่ละข้อ
- มีช่องรหัสผู้เข้าสอบและคำแนะนำการพิมพ์ที่ขนาด 100%

### การตรวจและความปลอดภัย

- ภาพที่ถ่ายใช้แสดงชั่วคราวและไม่บันทึกลงฐานข้อมูล
- ครูเลือกคำตอบ ยืนยันว่าเว้นว่าง หรือกำหนดเป็นรอตรวจได้
- คำตอบกำกวมต้องไม่มีคะแนนจนกว่าครูยืนยัน
- ใช้รหัสผู้เข้าสอบแทนชื่อจริงเป็นค่าเริ่มต้นด้าน privacy

### รายงานและข้อมูล

- แสดงจำนวนผู้เข้าสอบ คะแนนเฉลี่ย สูงสุด ต่ำสุด และจำนวนรอตรวจ
- แสดงอัตราตอบถูกรายข้อและรายการผลตรวจ
- การตรวจทานต้องคำนวณคะแนนใหม่จากเฉลยเดียวกัน
- export CSV และ backup JSON ต้องทำใน browser โดยไม่ส่งข้อมูลออกจากเครื่อง
- restore ต้องตรวจ schema ก่อนเปลี่ยนข้อมูลและทำใน transaction

## 5. Non-functional Requirements

- TypeScript เปิด `strict` และไม่มี `any` ที่ไม่ได้อธิบายเหตุผล
- แยก UI, domain logic, persistence และ service boundary
- ใช้งานได้ตั้งแต่ 320px ถึง desktop และ touch target หลักไม่น้อยกว่า 48px
- ใช้งานด้วย keyboard ได้ มี focus state, skip link และรองรับ reduced motion
- Footer และเครดิตครบสามบรรทัดทุกหน้า
- ไม่มี secret หรือ credential ใน client bundle
- การบันทึก/ลบข้อมูลที่เกี่ยวข้องต้อง atomic และใช้ stable identifier

## 6. ขอบเขตที่ยังไม่เป็น Production

- OMR อัตโนมัติด้วย OpenCV.js และ calibration กล้องหลายรุ่น
- Cloudflare Workers/D1/R2, authentication และการ sync ข้ามอุปกรณ์
- ระบบออก/revoke/ย้าย Activate Key จากศูนย์กลาง
- AI API ทุกชนิด

ความสามารถเหล่านี้ต้องได้รับ design, security/privacy review และคำสั่งเริ่มงานแยกก่อนเชื่อมบริการจริง

## 7. Acceptance Criteria

- `npm run lint`, `npm run test`, `npm run build` และ `npm run format:check` ผ่านจริง
- workflow สร้างข้อสอบ → พิมพ์ → บันทึกผล → ตรวจทาน → รายงาน ทำได้ในเครื่อง
- automated tests ครอบคลุม scoring, ambiguous answer, validation, persistence และ backup/restore
- production build มี manifest, service worker และ app icons
- `.env` ถูก ignore และ `.env.example` ไม่มี secret
